ProgressGraph

Deterministic game progress tracking without a framework

Overview

ProgressGraph is a lightweight runtime toolkit for tracking, validating, and persisting game progress using named flags and explicit dependency rules.

It is not a quest system, dialogue system, or gameplay framework. ProgressGraph provides a clean, deterministic layer for answering questions like:

  • Has this event already happened?
  • Can this action occur yet?
  • What progress conditions are missing?

Core Concepts

Progress Flags

A progress flag represents a discrete piece of game state.

Examples:

  • Boss.Defeated.Factory
  • Key.Collected.Red
  • Tutorial.Completed
  • Door.Opened.MainGate

Flags are:

  • Identified by string IDs
  • Boolean in value
  • Serializable
  • Explicitly controlled
Progress.DefineFlag("Boss.Defeated.Factory");

One-Way vs Reversible Flags

By default, flags are one-way. Once set, they cannot be unset. 

Progress.DefineFlag("Boss.Defeated.Factory", oneWay: true);

Reversible flags allow toggling and are useful for world states: 

Progress.DefineFlag("Area.Power.On", oneWay: false);

Dependencies

Flags may declare dependencies on other flags. A flag cannot be set unless all its requirements are met. 

Progress.Require("Door.Opened", "Key.Collected");

Public API Summary

Defining Flags

Progress.DefineFlag("Key.Collected");
Progress.DefineFlag("Door.Opened");

Declaring Dependencies

Progress.Require("Door.Opened", "Key.Collected");

Querying State

Progress.IsSet("Key.Collected");
Progress.CanSet("Door.Opened");

Inspecting Missing Requirements

var unmet = Progress.GetUnmetRequirements("Door.Opened");

foreach (var req in unmet)
{
    Debug.Log($"Missing: {req}");
}

Setting and Resetting Flags

Progress.Set("Key.Collected");
Progress.Set("Door.Opened");
Progress.Reset("Area.Power.On"); // Only if reversible

Resetting All Progress

Progress.ResetAll();

This clears all flag states without removing definitions or dependencies.

Save & Load Integration

ProgressGraph does not enforce a save system. Instead, it exposes a snapshot that can be saved using any solution.

Export

ProgressSnapshot snapshot = Progress.Export();

Import

Progress.ResetAll();
Progress.Import(snapshot);

This design ensures explicit lifecycle control and compatibility with any save framework.

What This Asset Is Not

ProgressGraph intentionally does not include:

  • Quest definitions
  • Dialogue trees
  • Visual editors
  • UI systems
  • Timeline logic
  • Save file management

It is designed to integrate cleanly with custom gameplay code.

Recommended Usage

ProgressGraph works best as:

  • A foundation layer for quests or objectives
  • A world-state tracking system
  • A replacement for scattered boolean logic
  • A debugging aid for progression logic
